Blog Under Attack: Troubleshooting and Fixing a CDN Supply Chain Poisoning Incident

JI,XIAOYONG • Published on 2025-12-22

Recently, I discovered that my blog was automatically redirecting to third-party scam websites when browsed on mobile devices. After troubleshooting, I found that the CDN used by the blog was a victim of a supply chain poisoning attack. This article documents the entire investigation and repair process.

Symptoms

  • When browsing the blog on a mobile phone, the page automatically redirects to a scam website.
  • Mainly affects mobile users.
  • Occasional redirects also occur on PC.

Root Cause

cdn.staticfile.net Supply Chain Attack

After investigation, it was found that cdn.staticfile.net, used by this blog, suffered a supply chain attack in 2024. This was a large-scale attack related to the Polyfill.io incident.

Attackers gained control of the CDN source and injected malicious code into JavaScript files, redirecting users (especially mobile users) to scam sites.

Affected CDNs include:

  • cdn.staticfile.net ❌
  • bootcdn.net ❌
  • polyfill.io ❌
  • Several other domestic Chinese CDNs

Affected Resources in this Blog

Resource Original CDN Risk Level
Highlight.js cdn.staticfile.net ⚠️ High
Font Awesome cdn.staticfile.net ⚠️ High
MathJax cdn.staticfile.net ⚠️ High
Google Fonts fonts.loli.net ⚠️ Medium

Repair Solution

1. Replace the Poisoned CDN

Replaced all instances of cdn.staticfile.net with secure and reliable CDNs:

- https://cdn.staticfile.net/highlight.js/11.7.0/highlight.min.js
+ https://cdnjs.cloudflare.com/ajax/libs/highlight.js/11.9.0/highlight.min.js

- https://cdn.staticfile.net/font-awesome/6.4.0/css/all.min.css
+ https://cdnjs.cloudflare.com/ajax/libs/font-awesome/6.4.0/css/all.min.css

- https://cdn.staticfile.net/mathjax/3.2.2/es5/tex-mml-chtml.js
+ https://cdn.jsdelivr.net/npm/mathjax@3/es5/tex-mml-chtml.js

2. Smart Font CDN Switching

To balance the experience for both domestic (China) and international users, I implemented a smart font CDN switcher:

User CDN
Domestic (China) google-fonts.mirrors.sjtug.sjtu.edu.cn
International fonts.googleapis.com

Implementation Logic:

  1. Check localStorage cache (7-day validity).
  2. If no cache, prioritize trying the domestic SJTUG mirror.
  3. If loading fails, automatically roll back to Google Fonts.
  4. On the last day, silently refresh the cache in the background.

Other Optimizations

During the investigation, I also fixed the following issues:

Dark Mode Flickering (FOUC)

Problem: When switching pages, a white background would flash before turning dark.

Cause: localStorage.getItem('theme') might return 'auto', but the CSS only recognized 'light'/'dark'.

Fix: Immediately calculate the effective theme value in the <head>:

const saved = localStorage.getItem("theme") || "auto";
const systemPrefersDark = window.matchMedia(
  "(prefers-color-scheme: dark)"
).matches;
const effective =
  saved === "auto" ? (systemPrefersDark ? "dark" : "light") : saved;
document.documentElement.setAttribute("data-theme", effective);

Homepage Infinite Scroll Failure

Problem: Scrolling to the bottom failed to load more articles.

Cause: The search.json path was missing the /blog prefix, resulting in a 404 on GitHub Pages.

Fix:

- fetch('/search.json')
+ fetch(basePath + '/search.json')  // basePath = '/blog'

Mobile Hover Persistence

Problem: On mobile, the TOC and menu highlights wouldn't disappear after being touched.

Cause: The :hover state persists on touchscreens.

Fix: Use @media (hover: hover) to only apply hover effects on devices that support mouse hovering.

Lessons Learned

  1. Don't blindly use domestic (Chinese) CDNs: Many so-called "acceleration" mirrors have questionable security.
  2. Regularly check third-party dependencies: Especially CDNs and npm packages.
  3. Prioritize official CDNs: Such as cdnjs.cloudflare.com or cdn.jsdelivr.net.
  4. Test on mobile devices: Supply chain attacks often specifically target mobile users.
